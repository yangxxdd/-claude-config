# GTS 日报填数后的自审纪律（用户明确要求）

用户原话：**"以后我给你源数据，你做好后，自己要审查清楚，确认 100% 可以正确对外输出的（数据以及结论等的正确逻辑性）。"**

**Why**: 日报数据会直接给王总/秦总/制作人看，写一大堆结果被别人挑出问题，用户会很难做。演示数据可以凑合，真实源数据不行。

**How to apply**: 每次收到 9 月真实源数据、填完 Base 后，交付前做一轮自审，再对外：

1. **数据本身核一遍**（交叉校验，不是抽查）：
   - 三口径对账：m_ 安装 / b_ 安装(dnu) / s_ 安装 三个数互相对得上（有差异要说明口径）
   - 算术一致性：CPI=花费÷安装、CTR=点击÷展示、CVR=安装÷点击、次留成本=花费÷r1_cnt 全部反算验证
   - 合计行 vs 明细求和一致；无合计就取 2-3 个点手工验算
   - 素材名映射：Meta 广告组名称 → 素材名，逐条核对无错配（新命名规范按位置截取）

2. **结论/逻辑核一遍**：
   - 每日结论、问题追踪里的数字，必须和素材日报对得上（引用哪个数就是哪个数）
   - 关停判断套用关停规则逐条验：CPI 超线？花费>$50 且激活0？量级是否够判（DNU<20 不关）
   - 环比、达标判断的基数是否正确（vs 前日 vs 目标线 vs 7月基线，别混）

3. **只写存储字段**：formula/auto_number 不手写（会自动算），写了也不生效还可能报 READONLY。

4. **数据异常时**：用户会给男女/平台数据 → 调 [[gts-demographics]] 基线对比，判断是性别异常还是平台异常，写进问题追踪+警惕信号。
