# GTS 3留测试日报模板 → 幻宠交接文档

> 用途：让幻宠项目的 Claude 读完本文档后，在飞书 Base（多维表格）里复刻一套「幻宠」自己的日报模板。
> 本文档只讲**模板怎么搭**（结构、字段、公式、工作流、自审纪律），不含 GTS 专属的 KPI 数值——幻宠用自己的目标线即可。

---

## 0. 一句话说清这套模板是什么

每天收到投放源数据（Meta / BI / Singular 三份口径）后，填入一个飞书 Base，自动算出 CPI、留存、留存成本，并产出「给领导看的结论 + 问题追踪」。核心是：

- **5 张表 + 1 个仪表盘 + 1 个文档子页（每日简报）**
- **三个数据口径用字段名前缀区分：`m_` / `b_` / `s_`**
- **百分比字段名带 `%` 后缀**（如 `m_CTR%`、`b_R1%`），一眼分清是率还是数
- **字段顺序固定：m_ 最前 → b_ 中间 → s_ 最后**

---

## 1. Base 总结构

飞书 Base 里放 7 个块（block）：

| 块 | 类型 | 作用 |
|----|------|------|
| 素材日报 | 表 | 核心表，每天×每支素材一行明细 |
| 每日汇总 | 表 | 每天整体（按国家汇总）两行/多行 |
| 财务汇总 | 表 | 给财务看（含备注：未含税/退款/汇率） |
| 问题追踪 | 表 | 关停/异常素材的追踪台账 |
| 每日结论 | 表 | 给领导的浓缩判断（一句话结论等） |
| install投放日报总览 | 仪表盘 | 6 个图表：总花费/总安装/花费by素材/安装by素材/CPIby素材/留存R1by素材 |
| 每日简报 | 文档子页 | 领导直接看的图文简报（短句、观点先行） |

> 建法：`lark-cli base +base-block-create --type docx --name "每日简报"` 建文档子页；仪表盘在飞书 UI 里建，或用 lark-cli dashboard 命令。

---

## 2. 三口径字段命名规范（最重要）

**前缀** | **来源** | **含义** | **典型字段**
---|---|---|---
`m_` | Meta 前端 | 花费/展示/点击/转化/安装 | `m_花费` `m_展示` `m_点击` `m_CTR%` `m_CPC` `m_CVR%` `m_CPM` `m_安装` `m_CPI`
`b_` | BI（后台） | 激活 dnu + 留存人数 | `b_安装`(dnu) `b_r1_cnt` `b_r3_cnt` `b_r7_cnt`
`s_` | Singular（归因） | 安装/花费/留存 | `s_安装` `s_CPI` `s_r1_cnt` `s_r3_cnt` `s_r7_cnt`

规则：

1. **花费只看 `m_`（媒体账本）**，安装三口径并列，留存/成本以 `b_` 为主、`s_` 辅助。
2. **率（百分比）字段名带 `%`**：`m_CTR%` `m_CVR%` `b_R1%` `b_R3%` `b_R7%` `s_R1%`…；**人数/成本/金额不带**（`m_安装` `b_r1_cnt` `b_次留成本`）。
3. 字段里凡是「由公式算出来的」都设成**公式字段**（见下节），不要手动填。

---

## 3. 公式清单（飞书 Base 自动算，全部 `ROUND(...,2)`）

**留存率**（count / 安装 × 100）：
```
b_R1% = ROUND([b_r1_cnt]/[b_安装]*100,2)
b_R3% = ROUND([b_r3_cnt]/[b_安装]*100,2)
b_R7% = ROUND([b_r7_cnt]/[b_安装]*100,2)
s_R1% = ROUND([s_r1_cnt]/[s_安装]*100,2)
s_R3% = ROUND([s_r3_cnt]/[s_安装]*100,2)
s_R7% = ROUND([s_r7_cnt]/[s_安装]*100,2)
```

**成本**（花费 / 人数）：
```
b_CPI = ROUND([m_花费]/[b_安装],2)     # 注意：分子是 m_花费，分母是 b_安装
s_CPI = ROUND([m_花费]/[s_安装],2)     # s_CPI 直接用 Singular 给的 eCPI 也行，但公式口径统一
b_次留成本 = ROUND([m_花费]/[b_r1_cnt],2)
b_3留成本 = ROUND([m_花费]/[b_r3_cnt],2)
b_7留成本 = ROUND([m_花费]/[b_r7_cnt],2)
s_次留成本 = ROUND([m_花费]/[s_r1_cnt],2)
s_3留成本 = ROUND([m_花费]/[s_r3_cnt],2)
s_7留成本 = ROUND([m_花费]/[s_r7_cnt],2)
```

> 关键点：`b_CPI` 的分子用 `m_花费`（媒体账本口径），分母用 `b_安装`（BI dnu）。这是对账最容易出错的地方。

## 4. 素材日报表（核心，逐字段）

字段顺序（视图可见字段顺序，m_ 前 → b_ 中 → s_ 后）：

```
1. 维度 7：日期 / 出价方式(install·AEO) / 国家(美国·菲律宾) / 素材类型(V视频·P图片) / 素材名称 / 素材方向(9值) / 标记(🟢正常·🟡观察·🔴关停)
2. m_ 9：m_花费 m_展示 m_点击 m_CTR% m_CPC m_CVR% m_CPM m_安装 m_CPI
3. b_ 11：b_安装 b_CPI b_r1_cnt b_r3_cnt b_r7_cnt b_R1% b_R3% b_R7% b_次留成本 b_3留成本 b_7留成本
4. s_ 11：s_安装 s_CPI s_r1_cnt s_r3_cnt s_r7_cnt s_R1% s_R3% s_R7% s_次留成本 s_3留成本 s_7留成本
5. 基线 6：历史CPI 历史CPM 历史CTR% 历史CVR% 历史D1% 历史D3%   （幻宠用自己上一轮的老素材基线作对比锚点）
6. 备注
```

**分组**：视图按 `[日期, 出价方式]` 两级分组（每天一个组，组内再分 install/AEO）。

**素材方向 9 值**（GTS 用，幻宠换成自己的方向脑图）：视频-黑帮入会/氛围、视频-角色展示/招募、视频-复仇逆袭、视频-战斗、图片-角色展示、图片-美漫分镜、图片-幽默经营、图片-擦边/命运反转、清洁复测。

**标记规则**：默认 🟡观察；关停标 🔴；DNU<20 不关停只标 🟡。

## 5. 每日汇总 / 财务汇总

两表结构几乎一样（`日期 + 国家 + m_9 + b_11 + s_11`）：

- **每日汇总**：每天按国家一行（比如 1 天 = 美国一行；如果有菲律宾，同一天 = 美国一行 + 菲律宾一行）。**不要放「核心结论」字段**（结论单独放每日结论表）。
- **财务汇总**：同上，但**多一个「备注」字段**（写清楚口径：未含税/退款/汇率等）。

## 6. 问题追踪表（8 维度）

| 字段 | 类型 | 取值 |
|------|------|------|
| 编号 | text | 如 GTS-001 |
| 素材名称 | text | |
| 发现日期 | datetime | |
| 问题类型 | select | CPI超标 / 0激活 / 留存不达标 / CTR-CVR异常 / 环比波动大 / 其他 |
| 严重度 | select | 🔴严重 / 🟡观察 |
| 状态 | select | 🔴待解决 / 🟡处理中 / 🟢已解决 |
| 处理措施 | text | 关停 / 观察 / 减量 / 加量 |
| 问题描述 | text | **必须带关键数字**，如「7/9 D1=0%（0/12），同时 CPI $3.98 超线，双杀」 |

> 写问题描述的原则：**数字要能反查回素材日报**，不能写「留存差」这种没有数字的空话。

## 7. 每日结论表（5 角度 + 环比）

| 字段 | 说明 |
|------|------|

## 8. 数据时间线（留存滞后，最容易搞错）

**每天同时做两件事：判「当天效率」+ 补「昨天留存」。**

- **当天能拿到**：Meta 花费/展示/点击/安装（m_）、BI dnu（b_安装）。
- **留存滞后**：源数据**不含当天实时留存**。D1 次日才有，D3 第 4 天才有，D7 第 8 天才有。
- 所以第一天填完只有效率数据，留存列先留空，第二天回填前一天的 D1，第 4 天回填 D3……以此类推。

---

## 9. 每日工作流

1. 收三口径源数据（Meta / BI / Singular 的 Excel）
2. 解析 → 按素材名映射 → 填**素材日报**（m_/b_/s_ 数据 + 日期/国家/出价方式）
3. 填**每日汇总**（按日期×国家汇总）、**财务汇总**（带备注）
4. 写**每日简报**（文档子页，短句观点先行）→ 和用户对齐
5. 确认后回填：**每日结论** + **问题追踪**
6. 留存列后续天回填

---

## 10. ⭐ 自审纪律（用户明确要求，必须写进工作流）

**每次填完源数据、对外输出前，必须自审到 100% 正确，不许交付有错的东西等领导挑。**

1. **数据核一遍**（交叉校验，不是抽查）：
   - 三口径对账：m_安装 / b_安装 / s_安装 互相对得上（有差异要说明口径）
   - 算术反算：CPI=花费÷安装、CTR=点击÷展示、CVR=安装÷点击、次留成本=花费÷r1_cnt 全部验证
   - 合计行 vs 明细求和一致；无合计就取 2-3 个点手工验算
   - 素材名映射逐条核对无错配
2. **结论/逻辑核一遍**：
   - 每日结论、问题追踪里引用的数字，必须和素材日报对得上
   - 关停判断套关停规则逐条验；环比/达标判断的基数别混（vs前日 / vs目标线 / vs老素材基线）
3. **只写存储字段**：formula / auto_number 不手写（自动算）。

---

## 11. 幻宠特有：菲律宾的处理

- **国家字段直接内置 `菲律宾` 选项**（GTS 模板的国家字段就是「美国·菲律宾」两值，幻宠照用即可）。
- 每天**菲律宾单独一行**（和美国的行并列），每日汇总按「日期 × 国家」两行。
- 简报/结论里**菲律宾单独一段**，不要和美国混在一个数里说。
- 老素材的**男女占比、平台占比**要预先存一份基线（7月那种），数据异常时调出来对比：判断是「性别异常」还是「平台异常」，写进问题追踪 + 警惕信号。

---

## 12. 素材名映射逻辑

源数据的三个口径，素材标识不一样，要对齐到同一套素材名：

- **Meta**：广告组名称里有关键字 → 映射到素材名（如 `install-黑帮披萨店-hxj` → `P-披萨店`）。
- **BI**：素材 ID。
- **Singular**：Creative ID = BI 的素材 ID（同一个数字 ID）。
- 所以对齐顺序：Singular Creative ID ↔ BI 素材（同 ID 直接对应）→ 再用 Meta 广告组名称关键字 ↔ 素材名。

---

## 13. 老素材基线（对比锚点）

素材日报里放一组「历史基线」列（上轮 CPI/CPM/CTR%/CVR%/D1%/D3%），新素材留空。
作用：本轮某素材数据 vs 老素材差距大时，先拉男女/平台占比作对比分析定位根因。
